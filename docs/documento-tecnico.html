01

Resumen ejecutivo

UAJS Smart Campus centraliza los trámites y servicios de la Corporación Universitaria Antonio José de Sucre —solicitudes, PQRS, reservas de espacios y equipos, catálogo de recursos, eventos institucionales, notificaciones y reportes— en una sola plataforma web, detrás de una autenticación por rol y con persistencia real.

El sistema se construyó como una arquitectura distribuida real: un frontend en React que habla únicamente con un API Gateway, y siete microservicios independientes en Node.js/Express, cada uno con su propia base de datos PostgreSQL. Un séptimo microservicio adicional (búsqueda, sobre Elasticsearch) unifica la búsqueda de texto completo sobre los seis anteriores.

02

Stack tecnológico y justificación

React 18 + ViteSPA con recarga instantánea en desarrollo; adecuada para un panel con más de una docena de vistas internas por rol.
React Router 6Rutas anidadas y protegidas bajo /app/* sin recargar la página; guardas de ruta por sesión y por permiso de módulo.
Node.js + ExpressMismo lenguaje en todo el stack (JavaScript de punta a punta), lo que baja la curva de entrada del equipo; es además el stack recomendado por el proyecto integrador.
Microservicios + API GatewayCada dominio (usuarios, solicitudes, reservas...) se desarrolla, prueba y podría desplegarse por separado — es justamente el objeto de estudio de la asignatura.
PostgreSQL, una base por servicioRefuerza la independencia real entre microservicios: ninguno puede leer directamente los datos internos de otro.
Sequelize (ORM)Evita SQL manual repetido para los CRUD y mantiene el esquema de cada servicio versionado como código.
JWT compartidoAutenticación sin estado: cada microservicio valida el mismo token con el mismo secreto, sin depender de una sesión centralizada.
ElasticsearchUna búsqueda de texto completo consistente sobre seis bases de datos distintas no es viable con LIKE; se centraliza en un índice aparte.
DockerLevanta Postgres y Elasticsearch de forma reproducible en cualquier máquina del equipo, sin instalación manual.
03

Arquitectura del sistema

Frontend → API Gateway → microservicio correspondiente → su base de datos. El Gateway no valida tokens ni contiene lógica de negocio: cada microservicio protege sus propias rutas.

🗺️ Diagrama completo con puertos, rutas y sincronización interna en el Diagrama de Arquitectura.
MicroservicioPuertoResponsabilidad
usuarios-service4001Autenticación, registro, roles y permisos por módulo
solicitudes-service4002Solicitudes y PQRS: radicación, respuesta, asignación e historial
reservas-service4003Reservas de espacios/equipos, catálogo e historial de estado
recursos-service4004Catálogo de recursos físicos/tecnológicos, sincroniza stock con Reservas
eventos-service4005Eventos institucionales, inscripciones y cupo
notificaciones-service4006Notificaciones internas por usuario
busqueda-service4007Búsqueda unificada (Elasticsearch) sobre los seis anteriores
04

Especificación de endpoints

Todas las rutas pasan por el Gateway con el prefijo /api (ej. /api/solicitudes). Todas requieren JWT salvo /auth/login, /auth/register y /auth/forgot-password.

usuarios-service
POST/auth/login · /auth/register · /auth/forgot-password · /auth/reset-password
GET/auth/me · /usuarios · /usuarios/responsables · /permisos
PATCH/auth/perfil · /auth/correo-recuperacion · /usuarios/:id/estado · /usuarios/:id/rol · /permisos/:rol
DELETE/usuarios/:id
solicitudes-service
GET/solicitudes · /solicitudes/:id · /pqrs · /pqrs/:id/historial
POST/solicitudes · /pqrs
PATCH/solicitudes/:id/responder · /pqrs/:id/responder · /pqrs/:id/asignar
DELETE/solicitudes/:id
reservas-service
GET/reservas · /reservas/catalogo · /reservas/:id/historial
POST/reservas
PATCH/reservas/:id/estado · /reservas/equipos/sync (interno)
DELETE/reservas/:id
recursos-service
GET/recursos · /recursos/:codigo/historial
POST/recursos
PATCH/recursos/:codigo · /recursos/:codigo/estado
DELETE/recursos/:codigo
eventos-service
GET/eventos · /eventos/:id/inscritos
POST/eventos · /eventos/:id/inscribir
PATCH/eventos/:id · /eventos/:id/estado
DELETE/eventos/:id
notificaciones-service
GET/notificaciones
POST/notificaciones
PATCH/notificaciones/:id/leida · /notificaciones/marcar-todas
DELETE/notificaciones/:id
busqueda-service
GET/buscar?q=...
PUT/buscar/documento (interno)
DELETE/buscar/documento/:tipo/:id (interno)

GET /health está disponible en los 7 microservicios y en el Gateway.

05

Frontend

15 páginas y 15 componentes reutilizables, 2 hooks propios, más de 15 rutas con React Router, uso extensivo de useState/useEffect, CSS con metodología BEM y modo oscuro completo mediante variables CSS.
